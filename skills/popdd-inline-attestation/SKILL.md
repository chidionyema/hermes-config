# POPDD Inline Attestation

## The Rule

**Every verification, every edit, every test run → append a signed receipt to the chain.** Not a separate script you remember to run. Not a post-hoc step. Inline, per-action, continuous.

## Prerequisites

- `@lux/popdd` (TS) or `lux-popdd` (Py) installed in the project
- `.lux/keys/agent.pem` exists (generated by `HmacSigner.loadOrCreateKey`)
- A `ReceiptChain` instance active for the current session

## The Pattern

### 1. Initialize on session start

```python
from popdd import HmacSigner, ReceiptChain
from pathlib import Path

KEY = Path(".lux/keys/agent.pem")
RECEIPTS = Path(".lux/receipts")
KEY.parent.mkdir(parents=True, exist_ok=True)
RECEIPTS.mkdir(parents=True, exist_ok=True)

signer = HmacSigner(HmacSigner.load_or_create_key(KEY))
chain = ReceiptChain(signer, agent_id="lux-agent")
```

### 2. Sign every verify action

```python
# After running the verifier:
chain.append(
    action="verify",
    target="calculateDiscount",
    proof={
        "verdict": "PASS",
        "passed": 10000,
        "total": 10000,
        "samples": 10000,
    },
)
```

### 3. Sign every test run

```python
# After pytest completes:
chain.append(
    action="test-run:complete",
    target="signalengine:critical-tests",
    proof={
        "verdict": "PASS",
        "passed": 69,
        "failed": 0,
        "exitCode": 0,
    },
)
```

### 4. Sign every edit

```python
# After writing/modifying a file:
chain.append(
    action="edit",
    target="src/pricing.py",
    proof={
        "sha256": "abc123...",
        "diffLines": 12,
        "file": "src/pricing.py",
    },
)
```

### 5. Save the chain on completion

```python
chain.save(f".lux/receipts/{datetime.date.today()}.jsonl")
chain.verify()  # → {valid: true, totalReceipts: N}
```

## The "Auto-Attach" Solution — Built ✅

The `popdd_agent.py` module is now deployed to all 3 projects. It provides:

| Feature | How |
|---------|-----|
| **Hot chain** | Chain stays hot across agent invocations — auto-loads from today's JSONL |
| **Auto-save** | Every `append()` auto-saves to `.lux/receipts/<date>.jsonl` |
| **3 action types** | `sign_verify()`, `sign_edit()`, `sign_test_run()` + generic `sign_generic()` |
| **Per-project singleton** | `PopddAgent.for_project("signalengine")` returns the same instance |
| **Key management** | Load-or-create at `.lux/keys/agent.pem` |
| **Zero deps** | Pure Python stdlib — no pip install needed |

### Usage in agent loop

```python
from popdd_agent import PopddAgent

# Initialize once at session start
agent = PopddAgent.at_path(".")

# After every verify:
agent.sign_verify("calculateDiscount", verdict="PASS", passed=10000, total=10000)

# After every edit:
agent.sign_edit("src/pricing.py", sha256="abc123...", diff_lines=12)

# After every test run:
agent.sign_test_run("critical-tests", passed=69, failed=0, exit_code=0)

# Verify the chain is intact:
result = agent.verify_chain()  # → {"valid": True, "total": N}

# Print the chain:
print(agent.summary())
```

### Architecture — Language-Agnostic Receipt Contract

POPDD's receipt format (JSONL) is the **language-agnostic bridge**. Every language writes receipts to `.lux/receipts/`. The CI gate reads receipts — it doesn't care what language wrote them.

```
┌─────────────────────┐
│   CI Gate (shell)   │  ← ONE script, all languages
│ reads .lux/receipts/ │
└──────────┬──────────┘
           │ checks receipts for every modified function
┌──────────▼──────────┐ ┌──────────▼──────┐ ┌──────────▼──────┐
│  TS: @lux/popdd     │ │  Py: lux-popdd  │ │  .NET: dotnet-  │
│  + popdd_agent.py   │ │  + popdd_agent  │ │  popdd (TODO)   │
└─────────────────────┘ └─────────────────┘ └─────────────────┘
```

**Do NOT port the PDD enforcement CLI to every language.** The receipt is the shared contract. Each language just needs a signing library.

**Missing:** .NET NuGet package (`dotnet-popdd`) with `HmacSigner` + `ReceiptChain` API, pure .NET crypto, zero external deps.

## Per-Project Setup

Each project needs a `popdd_verify.py` that:
1. Loads/generates the signing key
2. Creates or loads the day's receipt file
3. Signs the test run
4. Saves and verifies the chain

All three projects (LUX, Signal Engine, Prospector) already have this at `scripts/popdd_verify.py`.

## Checklist

Before claiming a task is done:

- [ ] POPDD key exists at `.lux/keys/agent.pem`
- [ ] Receipts directory exists at `.lux/receipts/`
- [ ] Every verify/run produced a receipt (not skipped)
- [ ] `chain.verify()` returns `{valid: true}`
- [ ] Receipt file saved (dated JSONL)
- [ ] Wrong-number check: is the receipt count correct? (Better no receipt than a wrong one)

## Anti-Patterns

| Don't | Do |
|-------|----|
| Run POPDD as a post-hoc script | Integrate into the agent loop |
| Sign "0 passed, 0 failed" | Assert at least one test file exists first |
| Guess numbers | Parse real output from pytest/verifier |
| Re-sign the same chain | Create a new chain per session |
| Skip signing because "it's just a quick edit" | Sign everything — that's the point |

## When to Skip

- Session that produces no output (research, reading docs)
- Pure config changes (editing `.gitignore`)
- User explicitly says "don't sign this"
