# Hermes Agent Configuration Backup

## What to Back Up

| Path | Contents | Criticality |
|------|----------|-------------|
| `~/.hermes/memories/MEMORY.md` | Project facts, contracts, lessons | 🔴 Critical — irreplaceable |
| `~/.hermes/memories/USER.md` | User preferences, behavior rules | 🔴 Critical — irreplaceable |
| `~/.hermes/skills/` | All agent skills (working knowledge) | 🟡 High — can be rebuilt from source |
| `~/.hermes/config.yaml` | Provider configs, tool settings, auth | 🟡 High — strip secrets |
| `~/.hermes/hooks/` | Event hooks | 🟢 Medium |
| `~/.hermes/cron/` definitions | Scheduled job configs | 🟢 Medium |
| `~/.hermes/state.db` | Session history (all past conversations) | 🟢 Medium — searchable history |

## Backup Strategy

**GitHub repo: `github.com/chidionyema/hermes-config`** (private)

- `~/.hermes/` is a git repo with remote pointing to hermes-config
- Auto-push cron runs every hour: commits + pushes any changed skills/memories/config
- `.gitignore` excludes: keys (`*key*`), secrets (`auth.json`), runtime data (`state.db`, `cache/`, `logs/`)
- Memories and config are plain text MEMORY.md/USER.md — diffable, reviewable, revertable

## How to Restore

```bash
git clone https://github.com/chidionyema/hermes-config.git ~/.hermes
# Then re-initialise keys, auth tokens, and runtime data (these are gitignored)
```

## What Is NOT Backed Up

- `~/.hermes/auth.json` — API tokens, session credentials (intentionally excluded for security)
- `.lux/keys/` per project — HMAC signing keys (per-environment, never committed)
- `.lux/receipts/` per project — POPDD receipt chains (can be regenerated by re-running tests)
- `cron/output/` — past cron job results (ephemeral)

## Auto-Push Setup

Created via Hermes cron system. See cron job named `hermes-config-auto-push`:
- Schedule: `0 * * * *` (every hour on the hour)
- Action: `cd ~/.hermes && git add -A && git commit -m "auto: sync" && git push origin main`
- Silent if no changes (git diff --cached --quiet check)
